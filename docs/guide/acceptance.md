# 行为验收

验收围绕用户操作和结果，不以按钮文字、日志文本或固定节点名称是否相等作为功能通过依据。主导航组织为概览、数据、设置；桌面弹幕为独立透明窗口，登录属于全局账号操作。

## 自动化与手动场景

| 场景 | 预期行为 |
| --- | --- |
| 启动和导航 | 默认进入概览；只展示数据和功能入口，无弹幕正文；统计和设置可访问，不出现未接通入口 |
| 桌面弹幕启动 | 选房不启动连接；窗口创建成功才接收，重复启动复用，失败提供重试 |
| 桌面弹幕锁定 | 调整模式可拖动缩放；锁定成功才隐藏工具栏并鼠标穿透，主界面可靠解锁 |
| 双窗口关闭 | 关闭桌面层停止接收并保留内存历史；重开跟随最新；主窗口最小化不影响桌面层，退出关闭所有窗口 |
| 桌面层恢复 | 保存位置尺寸、字号与背景透明度；重开不锁定，显示器变化不丢失可操作区域 |
| 未登录与账号恢复 | 不伪造账号；真实账号查询结束后提供登录或已登录状态；错误有恢复入口 |
| 扫码、刷新与关闭登录 | 展示可扫描二维码；刷新使旧请求失效；关闭停止轮询；晚到结果不能恢复已关闭的流程 |
| 扫码成功与退出竞争 | 成功只提交当前有效登录；退出后旧请求不能重存凭据或恢复账号；Keyring 故障明确反馈 |
| 重启恢复 | 从 Keyring 验证账号，并恢复记住房间的真实查询；恢复失败可重新输入 |
| 房间输入和换房 | 非法房间不发请求；候选查询失败保留当前房间；成功后才切换上下文与弹幕连接 |
| 断房与请求完成竞争 | 断房后旧查询不能恢复房间；停止旧连接并清理相应图片；历史统计仍可查看 |
| 定时采样 | QR 和房间分别消费自己的到期时间；网络未完成不重复发请求；房间成功后约 60 秒再采样，失败退避 |
| 弹幕连接 | 只有服务端鉴权确认后进入已连接；失败尝试有效候选服务并退避重连；手动停止后不自动恢复 |
| 消息积压与归属 | 仅当前房间、当前连接的消息可进入列表；消息有界、批量消费；用户控制不会被消息积压挡住 |
| 阅读与跟随 | 向上阅读时新消息不强制拉回；可查看未读提示并返回最新；停止接收后仍能阅读已接收内容 |
| 统计与清理 | 按真实采样时间展示；缺失数值保持缺失；每房间最多 2,000 条；清除仅影响确认时选定房间 |
| 图片生命周期 | 旧 URL 的晚到结果不能覆盖新图片；失败可重试；移除图片时释放 CPU/GPU/纹理注册引用 |
| 设置与重启 | 主题、窗口材质和透明度实际生效并恢复；原生材质需在目标 Windows 环境单独验证 |
| 保存与恢复 | 后台合并保存；正常关闭等待最后请求落盘；旧文件迁移保留原件；损坏文件不静默覆盖，明确重试先备份 |
| 错误与敏感信息 | 用户错误不含上游原始响应、Cookie、Token；弹幕内容不写入持久化或日志 |

## 检查方式

```powershell
cargo test
cargo test -p nanabobo-app ui::acceptance -- --ignored --test-threads=1
cargo test -p nanabobo-app --features native-acceptance --test native_desktop --locked
cargo test -p nanabobo-app --features native-acceptance --test native_desktop --locked -- --input
cargo fmt -p nanabobo-app -p nanabobo-core -- --check
cargo clippy -p nanabobo-app -p nanabobo-core --all-targets --no-deps -- -D warnings
cargo build -p nanabobo-app
./target/debug/nanabobo.exe
```

GPU 验收通过真实 Runtime/Scene 绘制与指针、键盘输入检查概览、换房、数据、登录与清理浮层，以及独立桌面弹幕的透明背景、最小尺寸、字号和持续消息阅读位置。截图及可访问性树输出到 `target/ui-acceptance/`；包含 960×600、1200×800、浅深主题和 2× DPI。测试使用本地虚构房间数据，不接触真实凭据；截图必须目视检查，非空画面与语义树通过不能代替遮挡和可读性验收。

`native_desktop` 使用主线程上的生产宿主和内存会话创建真实原生窗口，验证创建后连接、锁定与解锁反馈、关闭重开及退出释放。它通过显式测试 feature 启用，不访问真实账号或保存设置。鼠标穿透、置顶与透明合成还须通过 NanaUI 原生窗口探针及目标桌面实际点击验证，不能用离屏截图代替。

`--input` 使用内存会话、合成输入和真实原生宿主，验证登录弹窗焦点、房间号编辑与提交、导航、统计标签、清理确认及无障碍动作。它按宿主顺序调用 Runtime 分发与应用钩子，业务状态仅由真实 `Inbox → Wake → update` 更新。Windows 按键转换、IME 和屏幕阅读器仍须在目标桌面实测。

自动化测试使用内存凭据、受控完成事件和临时存储验证生命周期；无窗口场景可验证界面与输入，但不能代替真实 B 站服务、扫码和 Keyring 集成。跨窗口变更还需在最小尺寸与常用尺寸、浅色与深色下确认操作可达、滚动可用、弹层可关闭及内容无遮挡。

最终报告应分别列出已通过测试、已完成真实冒烟和未验证场景。没有执行的真实登录、断网或原生材质检查不能视为通过。
