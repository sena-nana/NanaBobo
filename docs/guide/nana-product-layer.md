# NanaBobo 业务边界

## 当前工作流

应用维护一个当前直播间。主窗口导航为概览、数据和设置，承担数据速览和功能启动；账号登录与退出是全局操作。弹幕正文只在独立桌面层显示。

1. 使用 B 站二维码登录并验证账号；二维码密钥只在 core 内存中，界面只收到安全扫码载荷。
2. 输入房间号查询房间信息；输入中的候选房间和当前已连接房间独立，换房成功后再切换上下文。
3. 选房成功只更新数据；从概览启动桌面弹幕，原生窗口创建成功后才开始接收。调整模式可拖动缩放、阅读历史；锁定成功后隐藏工具栏并穿透鼠标，从概览解锁。关闭停止接收，重开保留当前房间历史并跟随最新。窗口运行期间换房才自动连接新房间。
4. 约每 60 秒获取当前房间数据并记录时间戳；网络失败退避，缺失关注数保持缺失。当前 `viewer_count` 沿用上游 `online` 映射，不能仅依据字段名称断言它等于真实观众人数。
5. 在统计页选择房间查看趋势与历史，确认后仅清除所选房间快照；每房间最多保留 2,000 条。
6. 设置页控制全部外观项（主题、窗口材质、透明度、透明区域、标题栏跟随、圆角），并在重启后恢复。

## 状态与接口归属

`nanabobo-core` 拥有 B 站请求、凭据、认证提交和弹幕连接状态机，公开业务命令与 NanaBobo 模型。`AppState` 内部客户端、凭据和二维码会话不向宿主直接开放。核心事件使用 `CoreEvent`，可通过适配器继续输出既有命名事件。

宿主会话按认证、房间、弹幕、统计、资源和存储分离。异步请求通过身份校验和取消保持结果归属；认证凭据提交还在 core 内验证 generation，不能仅靠 UI 丢弃旧结果。独立定时器和单飞请求避免重复轮询；有界消息队列不阻塞控制事件。

两个窗口共享单个 Session，各自拥有 RuntimeDocument 和视图。桌面窗口状态由关闭、创建中、调整中、锁定中组成，通过带代次的窗口效果与完成事件驱动；旧窗口反馈不能影响新实例。关闭主窗口退出应用，最小化主窗口不影响桌面层。退出账号或断房关闭桌面层。

通用窗口、组件、滚动、图表、图片纹理和渲染能力属于 NanaUI 上游。应用只做 L3 业务装配，不复制上游实现，也不把 B 站协议或专属状态机移入 NanaUI。

## 数据边界

登录态仅保存在 Windows OS Keyring。B 站原始响应、请求头、Cookie 和 Token 不进入 UI 状态、日志或普通文件。

非凭据设置、记住房间和统计快照保存在 `%LOCALAPPDATA%/NanaBobo/state.json`，由后台合并写入并原子替换。首次运行兼容可执行文件旁的旧存储并保留原件；数据损坏时停止覆盖，明确重试后先备份再保存。

桌面层保存逻辑位置和尺寸、字号与背景透明度；不保存运行或锁定状态。默认 420×640、最小 280×240、字号 18、背景透明度 0%，文字保持不透明。恢复窗口时按当前显示器工作区校正，重开进入调整模式。

弹幕原文只在当前会话内存中。停止接收保留正在阅读的消息；断房和换房清理旧上下文；应用退出不保存弹幕。
